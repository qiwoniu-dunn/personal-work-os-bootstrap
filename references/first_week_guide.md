# 第一周：用起来，再决定要不要加东西

第一周是观察参考，不要求每天打卡、固定收口时间或一次导入全部历史。目标是少重复解释、能找回资料、知道下一步。

## 四个真实动作

1. 用一份或少量真实材料，走完读取、分类、确认、写入和读回。
2. 建立一个正在使用的主题，让文件能回答背景、当前状态、最近变化和来源；一个文件也可以。
3. 真实出现人物或多人协作需要时再用 people、team，不为填空制造档案。
4. 使用几次后做简短回顾；第 5 至 7 天可以作为参考，不设自动提醒或任务。

## 可以直接说

```text
处理这份材料，先告诉我新增了什么，建议更新哪里。
对照已有文件，看看这条进展该更新哪个状态。
这份材料以前处理过吗？没有新信息就不用再写。
回顾这个主题的当前状态，说明来源和仍未知的部分。
```

新对话不清楚背景时：

```text
请先读取这个工作目录的 README.md、AGENTS.md 和 CONVENTIONS.md，
再读取与我当前问题相关的主题主文件，说明实际读到了什么后继续。
```

如果工具无法访问本地目录，应说明限制，改为由用户提供必要文件；不声称已经自动接续。

## 回顾哪些变化

- 找到了什么，是否减少重复解释？
- 哪些材料仍未处理或无法读取？
- 是否出现重复文件、过期状态或难以找到的正式主本？
- 哪条规则增加了负担，是否只需修改一句说明？
- 哪些目录完全没有使用，可保持轻量而不强行填充？

先给判断和调整建议，按确认范围修改，不直接扩建、移动或删除。

## 成长而不膨胀

重复出现的摩擦、当前成本、尝试过的小调整及结果，是讨论新能力的依据。“用过一周、同一问题出现两次”只是参考，不是每个人必须达到的指标；涉及安全、隐私或数据丢失的风险立即处理。

每次只讨论一个确实有帮助的小能力，使用后复查是否减负。看板、周报、自动化、Git 流程与外部连接不随初始化默认启用。
