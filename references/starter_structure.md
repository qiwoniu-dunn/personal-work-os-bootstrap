# Starter 目录设计

默认建议三件套与五个轻量目录，按用户确认的需要裁剪：

```text
README.md       地图与背景
AGENTS.md       协作、权限与启动要求
CONVENTIONS.md  事实归属、更新与验证
workspace/      项目、事务和主题
people/         必要的人物事实与协作背景
team/           多人关系和分工
inbox/          待处理材料与来源归档
memory/         值得保留的日期事实
```

默认不用编号，不预建复杂层级。people 与 team 的职责要清楚；没有相关场景时可保持空或仅有入口说明，用户不需要时在方案中省略，验收按实际确认方案检查。

## 主题从一个文件开始

轻量主题先用 `workspace/主题.md`，包含背景、当前状态、行动、风险及来源。内容增长到需要区分长期背景和当前计划时，再经确认拆成：

```text
workspace/主题/
  README.md
  plan.md
```

同一主题的当前状态只有一个主文件。不是所有主题都必须项目化，也不必为小事项创建 README 与 plan。

## 内容增长时如何归位

| 内容 | 归位原则 |
| --- | --- |
| 稳定说明或方法 | 优先更新已有主题，独立长期内容才按需建 docs |
| 当前行动与依赖 | 更新已有 plan 或主题文件的当前状态段 |
| 正式交付物 | 按需进入该主题的 deliverables |
| 稳定引用素材 | 按需进入该主题的 assets |
| 被后续证据替代的旧阶段 | 先说明替代关系，经确认进入该主题的 history |
| 渲染、测试和缓存 | 进入该主题明确的临时位置，不当正式知识保存 |

这些是分类方向，不是初始化时必须创建的目录清单。归位旧文件仍需授权，不以“规则一致”为由批量搬迁。

## 不默认建设

不默认创建 system、dashboard、weekly、skills、脚本和自动化。不把“留了文件”说成自动提醒、全文检索或永久记忆已生效。Git、同步和备份按用户实际工具单独讨论，不把某个平台作为前提。

保留人的事实与团队关系能力，不导入他人的人名、公司、项目、目录编号、人格或固定作息。
