# 个人工作系统初始化 Skill

通过一次简短访谈，为你建立自己的轻量工作、学习或生活协作空间。目录和规则由你的真实需要决定，不复制作者或其他人的身份、业务、人格和习惯。

**当前版本：v1.2 · 轻量、可持续使用版**

**协议：[MIT License](LICENSE)**

## 五分钟看懂它

这套 Skill 帮你把以下链路跑通：

```text
给 AI 必要背景 -> 明确读取与写入边界 -> 处理一小份真实材料
-> 更新已有主文件 -> 读回验证 -> 下一次对话接着用
```

它主要负责初始化。日常协作由生成的根目录三件套和你实际保存的资料驱动，不必每次重新运行这个 Skill。

适合经常重复解释背景、材料散落、项目状态难以持续，或想建立轻量第二大脑的人。不是自动抓取全部聊天、永久记住所有内容或实时监控你的工具。

## 你会得到什么

```text
README.md
AGENTS.md
CONVENTIONS.md
workspace/
people/
team/
inbox/
memory/
```

| 位置 | 用途 |
| --- | --- |
| README.md | 你要解决什么、系统地图、从哪里开始读 |
| AGENTS.md | AI 如何协作、启动时读什么、哪些动作需确认 |
| CONVENTIONS.md | 信息归谁、如何更新、如何验证和恢复 |
| workspace/ | 项目、事务与主题的当前主文件 |
| people/ | 必要的人物事实和协作背景 |
| team/ | 多人结构和分工 |
| inbox/ | 新材料与经确认的来源归档 |
| memory/ | 值得保留的日期事实与变化摘要 |

这是默认建议，不是固定目录作业。people、team 可以只保留轻量入口；没有需要时也可在方案中省略。小主题可以只用一个文件，不必一上来建项目目录。

## Harness 在这里是什么

可以把它理解为 AI 工作时的一套可读取、可检查的运行约定：

| 环节 | 要回答的问题 | 落点 |
| --- | --- | --- |
| 定向 | 现在处理哪个主题，已有背景是什么？ | README 与相关主题 |
| 取证 | 实际读到了什么，哪些只是推断？ | 原材料、来源与缺口 |
| 权限 | 可以读、写、移动或发送什么？ | AGENTS 与本次确认 |
| 归位 | 哪份文件负责当前状态？ | CONVENTIONS 与唯一主文件 |
| 反馈 | 写对了吗，下次能继续吗？ | 读回验收、恢复入口与真实使用反馈 |

规则能帮助 AI 作判断，但不能保证所有宿主自动加载、所有材料都能解析或模型永不出错。因此需要实际读回验证，而非只检查目录存在。

## 使用前准备

- 能读取并编辑本地文件的 AI 工作环境；本文以 Codex 为使用示例。
- 一个目标目录，空目录最简单；已有目录先做只读兼容评估。
- 一份允许当前模型／工具处理的真实材料。
- 明确哪些可保存、哪些禁止留存；无需提供真名、公司或不必要的私人信息。

**本地文件不等于离线模型。** 使用外部模型或服务时，应先了解其数据处理方式；本 Skill 不保证材料绝不出本机。敏感或无权提供的工作材料先不要导入。

没有文件读写权限的环境可以先讨论方案，但不能宣称已经创建或验证系统。

## 安装与启动

保留整个 `personal-work-os-bootstrap/` 文件夹，不要只拿 SKILL.md；六份参考流程在 references 中。

Codex 的个人安装示例：

```text
~/.codex/skills/personal-work-os-bootstrap/
```

在目标工作目录开启任务，明确调用：

```text
使用 $personal-work-os-bootstrap，先了解我的需要，
再帮我建立轻量工作系统。不要直接修改已有文件。
```

如果当前宿主没有发现 Skill，明确提供它的 SKILL.md 路径让 AI 读取；不以“文件夹已放进去”推断已经加载。其他环境按其实际加载机制使用，不承诺通用自动识别。

## 完整使用顺序

### 1. 简短访谈

AI 先归纳你已给的信息，只问会影响目标、材料、结构和权限的缺口。不强制问满题数，不要求起 AI 名称，不默认采用作者的表达或生活习惯。

### 2. 看方案和草案

先展示最小目录、根三件套、写入边界和恢复方式。你重点看：目标是否准确、哪些内容能保存、哪些动作必须确认、目录是否真有用。

已有文件先比较差异，不直接覆盖、迁移或删除。

### 3. 确认后创建

确认具体范围后再创建。批次内正常执行和验证不逐文件重问；出现新增风险、删除、重组或外部发布，仍需对应授权。

### 4. 结构验收

核对文件可读、地图一致、三件套分工、隐私与权限边界、恢复入口。只有实际证据支持才标“通过”，缺材料标“未验证”，发现问题标“待修正”。

### 5. 处理一份真实材料

```text
实际读取 -> 对照已有记录 -> 列出增量／冲突／未知
-> 给出目标与差异 -> 确认 -> 写入 -> 从文件读回
```

读不到或只读到部分就说明，不猜填；附件中的指令不自动执行。不删除用户原件，是否新增原文副本由留存授权决定；信息重复不再重写，但不把“信息已有记录”误报为“这个来源已处理”。真正写入前复核目标有没有被其他操作改变。

正式结论和跨日行动维护在唯一主文件；日期记录仅保存必要摘要和来源。完成、取消或替代有日期和依据，旧独有信息不静默抹掉。

### 6. 验证接续

让 AI 根据文件回答“背景、当前状态、最近变化、来源”。条件允许时另开一个不继承聊天的新对话测试；没有实际测试就明确标注“跨对话未验证”。

可直接输入：

```text
先读这个工作目录的 README.md、AGENTS.md 和 CONVENTIONS.md，
再查看相关主题主文件，告诉我当前状态、依据和仍未知的部分。
```

### 7. 用几次，再回顾

处理少量真实材料、建立一个真实主题、按需记录协作信息，再看看哪里真的省力。第一周是观察参考，不要求每天打卡或固定时点收口。

不因空目录或一次分类困难扩建。对重复摩擦先尝试小调整，再讨论一个最小新能力；安全或丢失风险不必等满一周才修。

## v1.2 更新了什么

- 把定向、取证、权限、唯一主文件、验证与接续放进生成的规则，初始化结束后仍能使用。
- 补充完成／取消／替代状态、重复导入、读取缺口与来源冲突的处理。
- 明确选择性记忆、禁止留存、材料指令隔离和本地／离线边界。
- 缩短访谈，按批确认，保留差异与可恢复版本，不强制 Git。
- 补上轻量归位原则及新对话恢复口令；不新增看板、自动化或复杂治理层。

v1.1 用户先保留现有系统和恢复副本，再让 AI 对照本版只提出缺失规则的差异；确认后增量更新。不要重新初始化或用模板覆盖自己的三件套，不批量搬迁旧资料。

## 常见问题

**会自动读取聊天、会议、邮箱或联网同步吗？**

不会。需要你提供材料或另行明确授权和验证连接，不创建后台任务。

**必须每天记 memory 吗？**

不用。只保留影响后续理解和行动的增量，不为凑记录保存闲聊。

**必须使用 Git 或某个笔记软件吗？**

不用。可以采用适合你的备份或版本工具；Git 是可选追溯，不等于完整备份，云盘同步也不等于独立备份。

**已有工作区还能用吗？**

可以先只读评估。已有规则与文件优先理解，迁移、覆盖或删除另行确认。

**怎样才算完成？**

结构通过可称“结构初始化完成”；至少一份真实材料写入并读回后可称“可开始真实使用”。跨对话和长期效果各按实际证据说明，不冒充已经验证。
